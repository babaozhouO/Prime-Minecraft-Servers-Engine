## 准备工作

开始之前，你需要：

- **一台服务器**（Windows 或 Linux 都可以）
- **安装 .NET 10 运行库**

  - Windows：下载安装 [.NET 10 Desktop Runtime](https://dotnet.microsoft.com/en-us/download/dotnet/10.0)（选 **Run desktop apps** 那个版本）
  - Linux：根据你的发行版，参考 [微软官方文档](https://learn.microsoft.com/dotnet/core/install/linux) 安装 .NET 10 Runtime

- 从以下渠道下载 PMCSsE 后端：

  - **GitHub**：[项目发布页](https://github.com/babaozhouO/Prime-Minecraft-Servers-Engine/releases) → 找到最新版本 → 下载 `PMCSsE_Backend_AllPlatforms.zip`
  - **QQ 群**：515093683 → 群文件 → `发行版` 文件夹

> ⚠️ **注意**：不要将程序解压到 `C:\Program Files`、`C:\Windows` 这类高权限文件夹，否则会导致程序没有权限写入配置文件和日志。

解压后你会看到一个 `PMCSsE_Backend` 文件夹，里面就是后端程序，还附带了一些一键运行脚本：

| 脚本文件 | 作用 |
|---|---|
| `start_foreground_win.bat` | Windows — 前台运行（有控制台窗口） |
| `start_background_win.bat` | Windows — 后台运行（无窗口） |
| `start_foreground_unix.sh` | Linux — 前台运行 |
| `start_background_unix.sh` | Linux — 后台运行 |
| `start_set_win.bat` | Windows — 首次配置（带 `first` 参数） |
| `start_set_unix.sh` | Linux — 首次配置 |

你可以直接双击或运行这些脚本，不用手动敲命令。当然，如果你想自定义参数，也可以手动在命令行中运行。

## 首次启动——配置向导

后端第一次运行需要进行初始化配置，告诉它"监听哪个地址、哪个端口、用什么密钥登录"。

### 第一步：带参数启动

推荐直接运行对应的一键脚本：

- **Windows** → 双击 `start_set_win.bat`
- **Linux** → 运行 `./start_set_unix.sh`

也可以手动带参数运行：

**Windows：**
```
PMCSsE_Backend.exe first
```

**Linux：**
```
dotnet PMCSsE_Backend.dll first
```

### 第二步：按提示操作

程序会一步步问你：

**① 选择监听地址**

```
请选择要监听的 IP 地址（输入对应序号）:
[0] All（所有IPv4和IPv6地址）← 大多数情况选这个
[1] 0.0.0.0（所有IPv4地址）
[2] ::（所有IPv6地址）
...
```

一般选 `0`（所有地址）即可。

**② 设置监听端口**

你需要输入一个纯数字端口号（1~65535），后端会在这个端口上等待前端连接。

```
请设置前端的连接端口，纯数字（1~65535）
应避免使用网络服务中的常用端口号
如 Web(80)，SSH(22)
```

默认推荐 `20000`，如果你想自己定一个也可以。程序会自动检查端口是否已被占用。

> 💡 如果你在 Linux 上使用 1024 以下的端口（如 443），需要以 root 权限运行程序。

**③ 设置访问密钥**

```
为保证安全，必须设置访问密钥
是否让程序自动生成一个（Y/N）
```

你可以选择：
- **Y**（自动生成）— 程序会生成一串复杂的密钥并显示在屏幕上，**请务必记下来**
- **N**（手动设置）— 自己输入一个不少于 8 个字符的密钥

> ⚠️ **极其重要**：访问密钥是你连接后端的唯一凭证，**丢失后没有任何办法找回**。请务必妥善保管！

### 第三步：完成配置

配置完成后，程序会提示：
```
已完成配置流程，此后不再要求使用可交互终端也不接受任何命令
所有操作均在前端的图形化界面上完成
请删除"first"启动参数后再次启动
```

此时可以关闭窗口。配置文件已经生成好了。

## 正常启动后端

首次配置完成后，以后再启动后端就**不需要**加 `first` 参数了。

直接运行对应的一键脚本即可：

| 运行方式 | Windows | Linux |
|---|---|---|
| **前台运行**（有控制台窗口） | 双击 `start_foreground_win.bat` | 运行 `./start_foreground_unix.sh` |
| **后台运行**（静默无窗口） | 双击 `start_background_win.bat` | 运行 `./start_background_unix.sh` |

也可以手动运行：

**Windows 前台：**
```
PMCSsE_Backend.exe
```

**Windows 后台：**
```
PMCSsE_Backend.exe background
```

**Linux 前台：**
```
dotnet PMCSsE_Backend.dll
```

**Linux 后台：**
```
dotnet PMCSsE_Backend.dll background
```

### 调试模式

如果遇到问题想查看更详细的日志，可以加上 `debug` 参数。例如：

**Windows：**
```
PMCSsE_Backend.exe debug
```

**Linux：**
```
dotnet PMCSsE_Backend.dll debug
```

也可以组合使用（后台 + 调试）：

**Windows：**
```
PMCSsE_Backend.exe background debug
```

**Linux：**
```
dotnet PMCSsE_Backend.dll background debug
```

### 小技巧：创建快捷方式

如果不想每次都打开命令行，可以给常用脚本创建快捷方式：

**Windows：**
- 右键 `start_background_win.bat` → **「发送到」→「桌面快捷方式」**
- 或者右键 → **「固定到开始屏幕」**
- 以后双击桌面图标即可一键启动后端

**Linux：**
- 给 `start_background_unix.sh` 创建桌面快捷方式（`.desktop` 文件）
- 或将其加入开机自启（crontab / systemd）

## 如何确认后端正常运行？

启动后，在控制台界面看到以下输出就说明后端已成功运行：

```
PMCSsE正在启动
项目网址：https://github.com/babaozhouO/Prime-Minecraft-Servers-Engine
将在 0.0.0.0:20000 上监听前端连接请求
```

如果没有报错信息，说明一切正常。现在后端已经在等待前端连接了。

## 如何安全关停后端？

有以下几种方式：

| 方法 | 说明 |
|---|---|
| **按 Ctrl+C** | 在运行后端的控制台窗口中按 `Ctrl+C`，后端会先安全关闭所有 Minecraft 服务端，再停止自己 |
| **发送终止信号（Linux）** | 如果用 systemd 或 Docker 托管后端，发送 `SIGTERM` 信号即可（systemd 默认会发这个信号） |
| **通过前端关闭（后续版本）** | 后续版本会在前端上添加"关闭后端"按钮，连接后端后可以在设置页面点击关闭 ⏳ *此功能暂未实现* |

> ⚠️ **切勿使用 `kill -9`（SIGKILL）或任务管理器强制结束后端进程**，这可能导致正在写入的配置文件损坏。配置文件损坏后**无法修复，所有管理器配置将丢失**。请始终使用 Ctrl+C 或 SIGTERM 来安全关停。

后端关闭时，你会看到类似这样的输出：
```
正在关闭所有MC服务器
正在关闭原生服务器
正在停止日志记录
程序已停止并释放资源
```

> ✅ 后端设计了对退出信号的自动处理，能安全地关闭它管理的所有 Minecraft 服务端进程，不会留下"孤儿进程"。

## 配置文件在哪？

启动后，后端的目录下会生成一个 `Configs` 文件夹，里面包含两个文件：

| 文件 | 保存的内容 | 备注 |
|---|---|---|
| `Config_Plaintext.dat` | 监听地址、端口号 | 不加密，但只包含非敏感信息 |
| `Config_Ciphertext.dat` | 访问密钥的验证信息、所有服务端管理器的配置 | **已加密**，用你的密钥加密 |

> ❌ **不要手动修改或删除这些文件**。如果删除，你需要重新用 `first` 参数进行配置。如果密文配置损坏，你设置的所有服务端管理器配置都会丢失。

## 日志文件在哪？

日志文件存放在 `Logs/主程序日志/` 目录下，按日期分文件保存：

```
Logs/
└── 主程序日志/
    ├── 2026-07-01.log
    ├── 2026-07-02.log
    └── 2026-07-03.log    ← 今天的日志
```

如果遇到问题需要排查，可以查看这些日志文件。
